About MCP — Model Context Protocol

What is MCP?
MCP (Model Context Protocol) is an open standard created by Anthropic that
defines how AI applications connect to external data sources and tools. Think
of it as a "USB-C port for AI" — a single, universal protocol that any AI app
can use to plug into any data source or tool, instead of building custom
integrations for each one.

Core concepts:
- Server: a lightweight program that exposes tools, resources, and prompts
  through the MCP protocol. Example: a server that wraps a weather API.
- Client: a protocol-level connector that maintains a 1:1 session with a
  server. It handles message framing, capability negotiation, and transport.
- Host: the user-facing application (e.g. Claude Desktop, an IDE, or a CLI
  chat app) that contains one or more clients. The host decides which servers
  to connect to and how to use their capabilities.
- Tool: a function the server exposes that the LLM can call (like an API
  endpoint). Tools have a name, a description, and a JSON Schema for inputs.
- Resource: read-only data the server exposes (like a GET endpoint). Resources
  have a URI and return text or binary content.
- Prompt: a reusable template the server offers. Prompts let servers suggest
  good ways to phrase requests to the LLM.

Transport options:
- stdio: the client launches the server as a subprocess and communicates
  through stdin/stdout. Best for local tools.
- HTTP with SSE (Server-Sent Events): the server runs as a web service. Best
  for remote or shared servers.

Why does MCP matter?
Before MCP, every AI application had to build its own integration for every
data source — an N×M problem. MCP turns it into N+M: tool authors build one
MCP server, and app authors build one MCP client, and they all work together.
